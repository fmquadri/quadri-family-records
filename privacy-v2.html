Privacy disclosure — Quadri Family Records v2

Published September 8, 2026.

This is a family-caregiver system for people who authorize collection of their records. Connecting a provider permits the read-only access shown on that provider's consent screen. Each patient's sources and report recipients are handled separately.

Collection and use

The system retrieves authorized health records, including demographics, allergies, conditions, medicines, immunizations, results, vital signs, encounters, procedures and clinical documents. It preserves original evidence, reconciles changes and prepares reviewed summaries. A connection may support repeated retrieval until revoked or expired. It does not change a provider's chart or direct treatment.

Storage and external processing

Records remain identified. They may be stored on family computers, in private GitHub repositories and in approved Microsoft cloud storage, including an employer-managed tenant where specifically authorized. Hosted reports use services including Vercel, Neon and Clerk. Approved external AI services, including OpenAI, Anthropic and Google, may receive identified material for analysis, drafting and review. These providers operate infrastructure outside the family's direct control. Their retention, access and model-training practices depend on the service and account settings; this application does not promise that all processing stays local or that every provider excludes training.

Reports are available only to authorized audiences. Adding a data source does not grant another person report access. Where configured, email notifications announce report availability without including clinical report content. Provider email setup and recipient preferences must be verified before notifications are enabled.

Authorization and credentials

You enter your provider password and any verification code on the provider's own sign-in page. The local collector stores continuation tokens and private keys in Windows Credential Manager. The optional HTTPS authorization relay is hosted on GitHub Pages: its initial request passes the temporary authorization code and state through that hosting infrastructure, then the page clears the browser address and forwards only to the local collector. PKCE and state checks bind completion to the initiating session. The relay page does not intentionally store or display these values or load analytics.

Retention, revocation and removal

You can revoke a connection through the provider or contact the operator to stop future collection. Revocation does not automatically erase records already collected. This system retains an audit history; copies committed to repository history, backups, external services or already downloaded by recipients may persist. Report withdrawal blocks future portal downloads but cannot recall downloaded copies. Discuss removal requests with the operator; immediate deletion of every existing copy is not promised.

Contact and changes

Contact operator Faisal Quadri through your existing caregiver contact or the contact associated with this application in the provider's developer program. Ask about source scope, recipients, external processing and current account settings before authorizing. A new source, recipient or materially different use requires the applicable authorization; this notice alone does not grant it.
